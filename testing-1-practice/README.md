# [Тестирование] Задание 1. Пользовательский сценарий и функциональные требования (ÉLAIRE)

## 1. Основной пользовательский сценарий (Happy path) «Клиент записывается на услугу»

```text
Клиент записывается на услугу в салон ÉLAIRE
│
├── 1. Выбор услуги (Экран 1: Каталог услуг)
│   ├── 1.1. Открыть каталог услуг салона
│   ├── 1.2. Выбрать интересующую категорию (Стрижки и укладки / Маникюр и педикюр / Брови и ресницы / Спа-процедуры)
│   ├── 1.3. Ознакомиться со списком услуг выбранной категории (название, описание, длительность, стоимость)
│   ├── 1.4. Выбрать желаемую услугу (клик по карточке услуги)
│   └── 1.5. Нажать кнопку «Записаться» для перехода к выбору даты и времени
│
├── 2. Выбор даты, времени и мастера (Экран 2: Бронирование слота)
│   ├── 2.1. Выбрать желаемого мастера (или оставить «Любой мастер»)
│   ├── 2.2. Выбрать дату посещения в интерактивном календаре
│   ├── 2.3. Просмотреть доступные временные слоты на выбранную дату
│   ├── 2.4. Выбрать свободный слот времени
│   └── 2.5. Нажать кнопку «Продолжить» для перехода к подтверждению
│
└── 3. Ввод контактных данных и подтверждение записи (Экран 3: Подтверждение записи)
    ├── 3.1. Проверить сводную информацию о записи (услуга, мастер, дата, время, итоговая цена)
    ├── 3.2. Ввести имя клиента
    ├── 3.3. Ввести номер контактного телефона
    ├── 3.4. (Опционально) Ввести комментарий к записи
    ├── 3.5. Нажать кнопку «Подтвердить запись»
    └── 3.6. Увидеть сообщение об успешном оформлении записи с деталями визита
```

---

## 2. Список функциональных требований по сценарию «Запись на услугу»

### Экран 1. Каталог и выбор услуги:
1. **Система должна** отображать список услуг, относящихся к выбранной категории, когда клиент нажимает на вкладку категории.
2. **Система должна** отображать для каждой услуги её наименование, подробное описание, продолжительность и стоимость.
3. **Система должна** визуально выделять выбранную услугу и делать активной кнопку «Записаться», когда клиент выбирает конкретную услугу из списка.
4. **Система должна** перенаправлять пользователя на экран выбора мастера, даты и времени с сохранением выбранной услуги, когда клиент нажимает кнопку «Записаться».

### Экран 2. Выбор мастера, даты и времени:
5. **Система должна** отображать календарь с возможностью выбора дат, блокируя выбор прошедших дней.
6. **Система должна** отображать список свободных временных слотов для выбранного мастера, когда клиент выбирает доступную дату в календаре.
7. **Система должна** визуально блокировать занятые временные интервалы и запрещать их выбор клиентом.
8. **Система должна** обновлять блок сводной информации о записи (дата, время, специалист), когда клиент выбирает время посещения.

### Экран 3. Ввод контактных данных и подтверждение:
9. **Система должна** отображать форму ввода персональных данных (имя, номер телефона, комментарий) и итоговые параметры записи перед подтверждением.
10. **Система должна** валидировать обязательные поля формы (проверять заполненность имени и корректность формата номера телефона) в момент нажатия кнопки «Подтвердить запись».
11. **Система должна** отправлять данные записи на сервер, резервировать время в базе данных и отображать экран успешного бронирования, когда клиент нажимает кнопку «Подтвердить запись» с корректно заполненными данными.
12. **Система должна** отображать понятное сообщение об ошибке и подсвечивать некорректные поля, когда обязательные данные не введены или заполнены с ошибкой.
